# 刚体旋转在 68 点阶段被拉回 0

状态：已完成。`vhap_monocular` 的关节正则不再对根旋转 `rot_neck` 往 0 拉。

对照图：
- 改前：`notes/gnm_uv/测试用图片/GNM v4 + face PCA150.jpg`
- 改后：`notes/gnm_uv/测试用图片/GNM v4 + PCA150 根旋转不拉0.jpg`

## 和 FLAME 脖子的关系

有关，但不是「FLAME 没优化脖子所以 GNM 也坏了」。

FLAME / VHAP 有两套旋转：

| 参数 | 作用 | `lmk_init_all` | 朝 0 的正则 |
|---|---|---|---|
| `rotation` | 整颗头相对世界的根旋转 | 可优化（在 `pose` 里） | **没有** |
| `neck_pose` | 头相对脖子/躯干的解剖关节 | 可优化（在 `joints` 里） | `reg_neck=0.3` |

所以 FLAME 对齐图像里的头姿，主要靠无正则的全局 `rotation`。解剖脖子仍在优化，但被正则压在 0 附近。本帧 VHAP：`rotation` 范数约 0.16，`neck_pose` 约 0.016。

另外 FLAME 脖子只有一个关节，下段脖子相对躯干几乎动不了；脸对齐了，渲染里脖子根仍可能和照片不完全同向。这是模型自由度限制，两边八格图里都能看到，不是这篇要修的点。

GNM 没有单独的解剖脖子。刚体阶段的 `rot_neck` 就是整颗头的根旋转，对应 VHAP 的 `rotation`，不是 `neck_pose`。

## 原因

`metric_reg` 在 `vhap_monocular` 里把 `reg_joint * ||rot_neck||²` 当成了 VHAP 的 `reg_neck`。等于把根旋转按解剖脖子去拉。68 点阶段身份和下巴会去补被拧回去的那部分点误差。

## 改法

`19676/GNM_Fit/fit_gnm.py`：`vhap_monocular` 的关节先验只留下巴和眼睛（对齐 VHAP 的 jaw / eyes），**去掉对 `rot_neck` 的拉回**。GNM 没有对应 `neck_pose` 的自由度，也就不加那一项。刚体 / shape 结束后打印 `rot_neck` 范数便于核对。

## 结果（第 0 帧，PCA150，v4 映射）

| | 刚体后 | 68 点后 | 整体误差 |
|---|---:|---:|---:|
| 改前（根旋转也正则） | 10.71° | 10.43° | 1.59 px |
| 改后（根旋转自由） | 10.73° | 10.69° | 1.53 px |

这一帧本来就没有被拧回 0；去掉错误正则后，刚体角几乎原样保留，点误差略降。输出目录：`gnm_fit_out/expression_v3/lmk_align_vhap_frame0_v4_exppca150_noroottoreg`。
